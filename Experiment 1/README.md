Software Engineering
UNDOX
Problem statement

Modern applications increasingly rely on automated workflows, APIs, database operations, and AI agents to modify files and business records. When an operation fails midway or produces an unintended result, restoring the original state can be difficult, especially when multiple dependent actions have already executed or other users have modified the same data. Traditional rollback mechanisms do not work across every system or external side effect, while blindly retrying operations can cause duplicate actions or further damage.

UNDOX addresses this problem through a recovery layer that records execution state, maps dependencies between operations, identifies recoverable failures, and generates verifiable recovery plans. It detects conflicting changes, supports compensating actions for completed operations, and maintains an auditable record of execution and recovery. Unsafe recovery attempts are flagged for manual review rather than executed automatically.

Target users:

Independent developers and software engineering teams building automation-heavy applications.

Startups integrating AI agents with databases, APIs, and business workflows.

DevOps and platform engineering teams managing scheduled jobs, migrations, and multi-step operations.

SaaS companies seeking safer execution, recovery, and accountability for automated tasks.
